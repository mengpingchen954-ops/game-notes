# 经典玩法 × 当下情绪 × 一条规则：单人90天执行计划

这是一份实验计划，不是“90天必出爆款”的承诺。目标是用有限时间筛出值得继续做的游戏，验证玩家分发，并找到一个有人愿意付费的开发者工具。游戏广告在实际到账前按零收入计算；课程在有人为具体工具/指导付费前不预制。

## 一、方法论：三个东西各管一件事

1. **成熟玩法管好玩。** 选玩家已经能理解的动作：滑块疏通、颜色排序、合并、接物等。保留清楚的目标、及时反馈、失败后想重来的空间。参考机制，不复制别人的关卡、美术、代码、商标、文案。
2. **当下情绪管点开。** 每周观察热榜、评论、弹幕，抽取处境和情绪，例如“临下班又来活”“消息误发后怕已读”。不要把流行人物、原梗图、原声、影视角色当作现成素材。
3. **一条规则让情绪发生在操作里。** 不是通关弹一句梗，而是玩家必须针对这个处境改变决策。规则须提前告知、有办法应对、能产生多局变化。

可照着做的两个候选：

| 核心玩法 | 原创情绪题材 | 只加一条规则 | 15秒视频里要拍到的反转 |
| --- | --- | --- | --- |
| 华容道式滑块疏通 | 《下班别被看见》 | 每成功拖动一次，领导在“看电脑/看出口”间切换；只能在看电脑时离开 | 通路刚清出来却走不了；再挪椅子，趁领导转头出门 |
| 颜色/物品排序 | 《紧急插单》 | 每四步从提前展示的队列送来一件新任务；必须给它留空位 | 眼看整理完，新任务来了；先清出一组接住它 |

第三、第四个原型不要预先硬定题材：第4天根据当周真实热度、版权风险和个人制作成本选。四个候选要尽量覆盖不同经典机制，避免只测试四种皮肤。

采集“网络热梗”时拆成三格：大家正在说的词或场面、背后的共同情绪、能否变成一个玩家可操作的障碍。比如“班味”只是搜索线索；情绪是下班前还得看人脸色；可操作的障碍才是领导会随着玩家每一步转头。跟风词下周可能过时，规则本身不能跟着失效。

**三个版本的对照：** 先做朴素图形的经典玩法版；再加原创情绪视觉和文案；最后只加那条情绪规则。若朴素版没人想重玩，换皮救不了游戏；若规则版没有更有意思的决策，就删掉规则。

## 二、选品闸门：先排雷，再做游戏

每周收集15至20个当下情绪/处境、5至8种成熟玩法；写成“一句话操作→障碍→反转”候选卡。只保留能在一屏演示、两天内做出可玩的组合。

**硬问题A：** 把梗图、台词和角色全部去掉，这游戏还想让人再玩一局吗？用朴素几何版让5至8名陌生人独立玩60至90秒，不提示他们重玩；记录是否主动再开以及原因。

**硬问题B：** 把玩法录成15秒视频，观众能看懂那个情绪笑点吗？给另一组5至8名没玩过的人看无旁白视频，问“目标是什么、哪里好笑或憋屈、玩家怎样反转”；能自己复述才算情绪进入了规则。

**直接淘汰：** 必须依赖未授权真人肖像/品牌/角色；不解释看不懂胜负；要联网、复杂AI、大量剧情或人工关卡才能成立；规则主要靠随机必输制造“节目效果”。

先验打分只用于比较和排队，不代表成功概率。每项打0至5分，再按权重折算到100分：

| 指标 | 权重 |
| --- | ---: |
| 玩法已有需求证据 | 15 |
| 去梗后仍愿意重玩 | 20 |
| 15秒内看懂情绪反转 | 15 |
| 情绪规则真的改变决策 | 15 |
| 一个人能低成本做好 | 15 |
| 能扩关或反复开局 | 10 |
| 素材、品牌及平台风险可控 | 10 |

**固定止损：** 每个微原型最多8至12小时、一个画面、一个情绪规则、3至5局/关，不接广告、不做完整美术。看不懂首屏只修一次；去梗后无人自发重玩就停机制；视频懂梗但不点试玩，可以把它留作内容，不做商业游戏。

**一张选品卡怎么写，以《下班别被看见》为例：** 成熟玩法=移动障碍到达出口；情绪=临下班被领导盯着；玩家动作=拖家具；唯一新增规则=成功拖动一次领导切换朝向；公平性=朝向始终可见，无效拖动不计步；去梗测试=把人和办公室全换成几何块，仍有人自发重试；15秒测试=陌生人能说出“路通了但要等他转头”；成本上限=两天5关。最后两项若实测不成立，卡片上的好点子也要淘汰。

## 三、两条漏斗分开记录

- 玩家：玩法视频曝光 → 点击试玩 → 首局完成 → 不经提示主动重玩 → 次日/第7日回访 → 实际广告展示 → 到账收入。
- 开发者：工程/排错视频曝光 → 有效观看 → 询问模板或留下需求 → 陌生人按公开价格购买 → 交付 → 退款和售后工时。

同一账号也分“玩家向玩法片”和“开发者向工程片”两个合集，各用自己的试玩/询问来源标识。播放量不是玩家留存，玩家点赞也不是开发者付费意愿。5至8人只用于找可用性问题，20至30位冷用户只用于方向性比较；样本不够，结论标“分发未验证”，不能标“市场不喜欢”。

**工具分工：** 优先用同一套轻量Cocos工程做各玩法原型，避免一个人重复造两遍。TapTap制造仅在确实能更快做某个原型或内容实验时使用；它的本地开发不等于可直接导出独立Cocos商业工程。发布、广告准入、备案、版号/测试、素材授权分别核对目标平台的现行规则。B站能发视频不等于游戏素材已获商业授权。

## 四、一个人的工作节奏

普通制作日控制在约6小时：两段各2小时做游戏或测试，1小时收集素材/剪辑，30分钟记数据，30分钟回复玩家和开发者。每周5天制作、1天集中发布和陌生测试、1天缓冲/休息；休息日只允许做20分钟记录。每周目标是1至2条玩家向玩法片和1条开发者向具体问题片，不追求日更。

每次开发顺手保留原始录屏，但只在安排了剪辑的日子做视频。玩家片只拍“目标→失败/意外→反转”，开发片只解决一个实在的问题，例如“领导状态切换时如何避免无效拖动也计步”。

**玩家向15秒固定镜头：** 0至2秒直接出现目标和处境；2至6秒玩家操作经典玩法；6至10秒出现情绪规则制造的受阻；10至13秒玩家采取对策；13至15秒出现清楚的输赢和真实试玩入口。不加一个游戏中不存在的假动作。标题讲处境而非“我又做了一个游戏”。

**开发者向短片固定镜头：** 先给出实机Bug或实现目标，再展示最小复现、关键实现、修复后结果；一条只讲一个技术问题。把完整工程过程录下来备用，但不日更流水账，不在未验证的原型上录几十节课。

## 五、每天做什么

日号是相对开始日期；当天未完成的内容不要用熬夜补齐，优先删功能或顺延后续发布。表中“内容/验证”包含当天的记录工作。

### 第1周：建立选品池与工作台

| 天 | 游戏/选品 | 内容/验证与当天产出 |
| --- | --- | --- |
| D01 | 设每周可用工时、固定实验预算、目标玩家和目标开发者；列出本轮绝不做的功能。 | 建两条独立数据表；产出一页90天约束。 |

| D07 | 缓冲/休息，最多20分钟核对4个候选是否仍能在两天做完。 | 不发片、不赶工；产出删减清单。 |

| D51 | 在目标机型实测性能、启动时间、前后台、断网或中断恢复。 | 录具体设备问题及修复，不剪成“秒上架”。 |
| D52 | 做20至30关的验收或无尽生成的死局检查；修阻断问题。 | 按实际进度做测试片，不用未完成的宣传镜头。 |
| D53 | 准备试玩页、图标、3张真实截图、版本号、反馈入口。 | 玩家片明确“测试版”，收集真实错误和建议。 |
| D54 | 邀请第一批20至30位新玩家，追踪每个来源、首局及自发重玩。 | 分别收玩家可玩性问题与开发者技术问题。 |
| D55 | 只修影响新玩家进入或完成首局的前三个问题。 | 发布一条工程片：真实测试中最值得复用的修法。 |
| D56 | 缓冲/休息；如果资质或平台条件缺失，停止“正式上架”倒计时。 | 产出当前渠道可行性和替代试玩渠道说明。 |

### 第9周：看玩家，不猜收入

| 天 | 游戏/选品 | 内容/验证与当天产出 |
| --- | --- | --- |
| D57 | 查看曝光→点击→开局→首关→再来一局的最大流失点。 | 发一条真实试玩复盘，注明样本量和来源。 |
| D58 | 只修最大流失点：可能是入口、首关、操作或加载；别同时调十项。 | 给修改前后版本打标签，保留对照记录。 |
| D59 | 第二批陌生玩家试玩，尽量沿用第一批渠道与邀请方式。 | 录他们第一次失败后的自然反应。 |
| D60 | 检查D1回访，若总用户很少，仅作为线索；不要用百分比宣称留存成功。 | 开发者片讲“我曾以为有趣但玩家没继续玩”的具体原因。 |
| D61 | 修明显的死局、重复劳动或低效关卡；决定补内容还是先改入口。 | 玩家片展示已经改善的真实前后，而非单纯换标题。 |
| D62 | 汇总玩家反馈，分“玩不懂/玩过一次够了/想继续/设备问题”。 | 列出下周一个最重要的改动和一个不做的改动。 |
| D63 | 缓冲/休息；复查双漏斗，游戏尚无变现不能叫“被动资产”。 | 产出第9周数据摘要及不确定性。 |

### 第10周：从实际工程抽一个工具

| 天 | 游戏/选品 | 内容/验证与当天产出 |
| --- | --- | --- |
| D64 | 列出本项目真正用过、开发者反复问到的3个模块。 | 向3至5位陌生开发者问现有做法、痛点和愿付费解决的问题。 |
| D65 | 选一个模块：例如关卡数据编辑器、通用滑块状态机或移动端适配；不做“大而全工具包”。 | 发布免费的最小示例，观察是否有人索要可用版本。 |
| D66 | 将模块从游戏抽离，在新空工程中接入一次，找到隐藏依赖。 | 录真实接入过程，写一句不适合哪些项目。 |
| D67 | 写安装、版本、示例工程、兼容范围和常见错误。 | 发一条“如何用这个模块省一步”的开发者片。 |
| D68 | 请2位没参与开发的人照文档接入；只改最大的理解障碍。 | 记录他们完成所用时间与需要你介入的次数。 |
| D69 | 明确售后边界、更新范围和公开定价草案；算个人时间成本。 | 发布候补页或公开询问，不用“课程限时名额”制造假需求。 |
| D70 | 缓冲/休息；若无人表达真实需求，暂停售卖，回去找问题。 | 产出工具是否值得继续的一页决策。 |

### 第11周：小范围真实付费验证

| 天 | 游戏/选品 | 内容/验证与当天产出 |
| --- | --- | --- |
| D71 | 固定最小版工具功能，附一个完整可运行示例和版本说明。 | 公布真实价格、交付内容、支持边界和退款规则。 |
| D72 | 向明确表达需求的人开放购买；不把熟人免费领取计入购买。 | 记录陌生购买者来源及购买前具体问题。 |
| D73 | 交付给首批用户，盯安装失败、兼容问题和售后工时。 | 开发者内容只展示已验证过的流程。 |
| D74 | 若至少一位用户卡住，改文档或示例；先不加新功能。 | 玩家侧正常维持1条玩法片，不用卖工具的片占满账号。 |
| D75 | 做工具最小修复版，同时回看游戏玩家回访和测试进度。 | 记录每单实际贡献：售价减平台成本、退款和个人支持时间。 |
| D76 | 收集下一批真实购买或明确拒绝原因；区分“很酷”和“愿买”。 | 写一个公开、可复现的使用案例。 |
| D77 | 缓冲/休息；无需当周就得出工具市场结论。 | 产出订单、退款、售后时间和未付费原因。 |

### 第12周：决定卖工具、做课程，还是回到选品

| 天 | 游戏/选品 | 内容/验证与当天产出 |
| --- | --- | --- |
| D78 | 继续修游戏最影响重复游玩的点；暂不为了广告加破坏节奏的弹窗。 | 发布阶段复盘：玩家与开发者结果分开讲。 |
| D79 | 检查工具是否有至少5名非熟人按公开价格购买，且售后能被售价覆盖。 | 若没有，记录是分发不足、问题不痛还是交付太重。 |
| D80 | 向已购用户询问他们是否需要“手把手完成一款可试玩作品”。 | 只统计实际愿意付费参加的回答，不统计客套点赞。 |
| D81 | 若工具购买成立且至少3人愿为指导付定金，写90分钟实操作坊大纲；否则跳过课程。 | 大纲写具体交付、准备条件、边界和退款安排。 |
| D82 | 若有意向，先做一次免费线下/线上小范围教学演练，检验时间和卡点。 | 收集学员在哪一步需要人帮忙，而不是先录十小时课。 |
| D83 | 明确是否继续主游戏、做第二轮选品、专做工具，按两条漏斗分别决策。 | 发布一条诚实复盘，不展示未到账的“收益”。 |
| D84 | 缓冲/休息；检查下月资源分配是否超过个人可承受工时。 | 产出下一轮保留/停止项目清单。 |

### 最后6天：只做有证据支持的下一步

| D85 | 若主游戏有回访，做一个最高优先级的内容更新；若无，整理新候选卡。 | 宣布下一步方向和依据，不声称爆款。 |
| D86 | 如满足D81条件，开启3至5人的小型付费实操作坊；否则改进工具示例。 | 明确目标是完成可试玩作品，不承诺赚钱或包过审。 |
| D87 | 有作坊则现场带做一个可验收步骤；没有则再访谈3位目标开发者。 | 记录各环节真实耗时、提问和中途退出。 |
| D88 | 修作坊暴露的文档问题；若没开班，完成第二轮选品的3张候选卡。 | 剪“一个常见错误如何修”的工程内容。 |

| D90 | **闸门2：** 确定下一个90天的单一主要投入：继续游戏、专注工具/教学，或重新选品。 | 写一页“证据、没证据、下一步、明确不做什么”；休息。 |

## 六、每个闸门如何决定

| 实际结果 | 下一步 |
| --- | --- |
| 玩家愿意再玩，视频能带来试玩，开发者无人付费 | 优先把游戏做稳；教程继续免费记录，不预制课程。 |
| 开发者为通用模块付费，玩家留存差 | 可继续做工具，但不要宣传“该游戏已经跑通广告盈利”；游戏回到选品。 |
| 视频被看，但无人试玩、也无人买 | 改视频到产品的入口/受众；不要误判为游戏或课程成功。 |
| 有试玩但样本不足 | 标注“分发不足、尚未验证”，继续找目标用户，不靠几人的D1百分比选冠军。 |
| 两侧都弱 | 停止加关和录课；保存可复用模块，重新找经典玩法与情绪组合。 |
| 两侧均出现真实数据，且扣除工时后能承受 | 才复制第二款、扩展工具或录制系统课。 |

## 七、每天只需填写的记录

日期 / 项目版本 / 今天有效开发时长 / 新玩家来源与人数 / 首关完成数 / 自发再开数 / 次日回访数 / 视频曝光与点击试玩数 / 开发者有效询问数 / 陌生原价订单数 / 退款与售后分钟 / 今日最大问题 / 明天只修一件事。

不要收藏一大堆未经验证的“网络热梗题材”。能从情绪变成规则、去梗后仍想重玩、15秒能拍出反转，而且一个人做得动，才进入下一天。
